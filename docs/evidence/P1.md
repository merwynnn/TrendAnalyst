## Where the work is cheaper, and why

The two dedup layers are worth distinguishing, because they save different things:

| Layer | Mechanism | Second-run effect |
|---|---|---|
| Payload | SHA-256 of the normalized batch (spec §5.2) | parsing, scoring and the LLM are skipped entirely |
| Fact | `UNIQUE (source_id, entity, metric, ts)` on `signals` | re-parsing an overlapping window inserts nothing |

Both are exercised by the fixtures: the recorded Reddit windows **overlap** (a
date-based watermark is a coarse filter), so run 2 parses 67 signals and stores none,
while run 3 sees an identical hash and does not parse at all.

## Bugs this phase found (all fixed)

1. **The leash refused instead of pacing.** The first recording collected 3 of 15
   subreddits and then had every further attempt refused — a silent under-collection,
   which is the worst possible failure for a discovery pipeline. `acquire()` now waits for
   a slot, with the sleep injected, and its loop is bounded so a clock that does not
   advance with sleep cannot hang a run.
2. **`dry_run` still wrote.** The flag skipped the ledger but not the lake; the dry-run
   test caught it.
3. **Budgets and plugins used different clocks**, so tests paced against real time
   (149 s → 9 s once they shared the caller's clock).
4. **`rowcount` is `-1` for `INSERT ... ON CONFLICT DO NOTHING`** in psycopg, so "new
   signals" was reported as `-1`. Counting now uses `RETURNING`.
5. **`FetchContext.max_items` was ignored by two collectors**, so a replay asked for more
   items than the fixture held — caught by a `FixtureMissError`, which is exactly why that
   error is loud.
6. **The registry mirror was assumed to exist.** A watermark lives on the `sources` row, so
   a run against an unsynced database silently failed to record cursors; the orchestrator
   now syncs before it starts.
7. **`slots=True` dataclasses have no `__dict__`** — the CLI's `--json` path crashed. It
   has a test now, because the gate runs that exact command.
