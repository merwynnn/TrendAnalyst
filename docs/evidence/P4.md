**"Balanced to zero unexplained spend"** needed a definition, and writing it found a real bug:

| Spend row | Explained when |
|---|---|
| `l0:<source>` | the `(run, source)` `run_source_log` entry exists **and matches** the ledger amount |
| `llm:<gate>:tokens:<key>` | a cached answer exists under that key for a real gate |

The first implementation compared a per-**source** ledger total against a per-**(run, source)** log
amount, so **71 of 113 rows were reported as unexplained** — every source ever collected in more than
one run. The bar was unreachable because the check was wrong, not because the ledger was. Verified by
a test written for exactly that case, and by the number going to zero.

## The honest gap: eBay's sold-versus-listed ratio

The obvious Tier-A signal — how many listings *sold* versus how many are *listed* — needs eBay's
Marketplace Insights API, which eBay restricts and has deprecated. Browse does not expose sold counts.
So `SS` is measured as **active supply** and `MP` gets a **real price distribution**, and the sold side
stays a gap. It is written in the plugin's docstring and here rather than inferred, because a
saturation proxy quietly standing in for a sold count is exactly the number this project refuses to
invent.

L2 is also **unvalidated against live eBay**: the credentials are blank, so the fixture in the tests is
hand-written and labelled as such. The parsing, the price spread, the credential gating, the budget
CAS and the degradation path are all tested; a live recording is the next step, exactly as the LLM
gates were proven before the key arrived.

## Bugs this phase found

1. **Reconciliation compared the wrong pair** (above): 71 false positives, and the P4 bar unreachable.
2. A **dry run reported "degraded"** — "the provider failed" about a run that made no request. The
   gateway now carries explicit `capped` and `dry_run` flags, because a monitor agent acts
   differently on "we chose not to spend" and "the provider is down".
3. **`MissingCredentialError` was a `RuntimeError`**, so a missing key was reported as a failure.
   It is now a `SourceSkippedError`: declined-to-call, not call-failed.
4. **The offline source filter silently found nothing** — a missing import swallowed by a bare
   `except Exception`. The gate probe now asserts the filter's own output, so an empty run cannot
   pass as a full one.
5. **`restore_budgets` asks for a clock for every source**, so an offline run died on the first source
   with no recording. A missing fixture is only fatal when a fetch actually needs it.
6. **A dry-run L2 counted signals it had not written** — the same class as the P1 `dry_run` bug that
   wrote the lake.
7. **The HTTP layer was GET-only**, and eBay's OAuth needs a POST. The client, the protocol and the
   fixture replayer gained `post`; fixtures carry the method for non-GET keys and stay backwards
   compatible. The alternative was faking the dance and pinning the fiction in a fixture.
