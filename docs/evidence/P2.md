## The decisions worth arguing with

1. **A category now requires a *buyable noun*.** The first mining run filed "Cat Jarman"
   (a Wikipedia biography) under *pets* and "children killing" (a headline) under *baby
   products*, because "cat" and "children" were keywords. Each category now has a `core` list
   of the things people actually buy, and a phrase must contain one. This is the single
   change that turned the table from noise into products.
2. **Wikipedia is excluded from mining, not from the pipeline.** Its entities are article
   titles — proper nouns by construction. It keeps its job as an *absolute demand baseline*
   for entities other sources surface.
3. **A signal's value is a percentile within its own source.** Upvotes, Reddit scores and
   pageviews are not the same unit, and summing them would produce a number with no unit at
   all. Each signal becomes a per-source attention percentile; the phrase's series is the sum.
4. **Substring collapse at mining time.** "circ saw", "blade circ saw" and "circ saw it still"
   are one title seen three ways, and they split the same evidence across three rows.
5. **The prune has a documented floor** (`min_keep=10`), because 5% of a thin lake is one
   candidate. Both numbers are reported, so the prune is visible rather than disabled.
6. **FE and the price half of MP are priors, not percentiles** — a documented deviation from a
   strict reading of §6.1. Nothing in the current sources can separate two ideas in the same
   category on shippability or price; inventing variation would be worse than admitting it.
7. **The eval labels are a baseline, stated as one.** `expected_keep` comes from a median
   split, not a judgement; the file says so, and the P3 Judge is what will replace it.

## Bugs this phase found (all fixed, all tested)

1. **The candidate-key order mismatch.** `upsert_candidates` returned keys phrase-first while
   the caller looked them up category-first, so candidates were written and snapshots were
   not — while the run reported success. It surfaced only because the report printed
   "0 new, 0 already present" instead of assuming. Fixed with one `candidate_key()` helper.
2. **n-grams crossed a field separator** (`entity | quote`), producing "cat jarman cat
   jarman" — a phrase nobody said. Extraction is now per segment.
3. **A fourth fad label** (`dead`) violated the schema's CHECK constraint. The constraint was
   right: staleness is a reason not to mine something, not a shape. It became L1's staleness
   filter.
4. **The first gate probe passed while failing.** It parsed JSON with a bare `python` (not on
   PATH here) and piped the payload into `python - <<HEREDOC`, where the heredoc *is* stdin —
   so both hashes were empty and compared equal. The check now reads the payload from a file,
   fails on a short hash, and fails fatally if the parse raises.
5. **Ten out of ten eval cases came out "keep"** — a case set that cannot catch the failure
   that matters most. The provisional threshold became a documented median split.
6. **`RUF046`/`PLR2004` noise, and four wrong test expectations** — worth recording because
   three of them (EWMA at α=0.5, a z-score against a population including itself, and
   `log_compress`'s 0.5 point) were *my* arithmetic being wrong, not the code's.

## What P3/P4 inherit

The scorer, the mining layer and the snapshot store are done and deterministic, so P3's Judge
gate has real inputs to judge and a versioned history to be compared against; P4's Tier-A
sources have exactly two functions to sharpen (`SS` and `MP`) without touching a signature.
The binding constraint is no longer code — it is collected data, which is what P4 is for.
