Five findings no mock could have produced (full write-up in [`LESSONS.md`](LESSONS.md) §6):

1. **Friendly model names are not model ids.** `gemini-flash`, `gemini-2.0-flash`, and
   `llama3.3-70b` on Cerebras — that key serves only `qwen-3.8-27b` and `gpt-oss-120b`.
2. **A models list is a catalogue, not a promise.** `GET /v1beta/models` *listed*
   `gemini-2.5-flash` while `generateContent` answered 404 *"no longer available to new users"*.
3. **A transient 503 was treated as permanent** — Gemini's *"experiencing high demand"* for the
   ~450-token drill prompt, while small prompts succeeded. The gateway now retries 429/5xx/timeout
   three times per chain entry and fails over at once on 404/402.
4. **One model per provider is a single point of failure**: with Groq unkeyed and Cerebras
   answering **402 (payment required)**, one overloaded model meant a gate outage. The chain
   carries a second Gemini model, documented as a deviation with this evidence behind it.
5. **The free tier is smaller than the spec's budgets assume.** Drilling exhausted the day's quota
   (~9.4k tokens). Spec §6.2's "Judge ~20 calls/night" is ~14k tokens at this size. That is now
   P4's decision (shrink the caps to the tier, fund a key, or let the 30-day cache carry the load).

## The Judge gate, offline and reproducible

The live drill needs a network and a quota. The gate needs neither, so the Judge is exercised by a
**replay of a real provider answer** — the recording comes from the drill itself
(`tests/data/llm/judge_verdict.json`, `gemini-3.6-flash`, 463+239 tokens):

```
$ uv run python -m trend_analyst.pipeline.orchestrator --judge-replay tests/data/llm/judge_verdict.json
judge run d1635f99… (replayed 2026-09-19T18:26:28…)
L3 judge: 1 judged over 1 call(s) (1 kept, 0 dropped, 1 ungrounded, 2 quotes stripped) via gemini
  batch 1: ok applied=1 missing=0 provider=gemini
```

**And the recorded verdict is marked `ungrounded`: the real model cited URLs the pipeline never
collected, and the grounding rule stripped both quotes.** The first live advice the system ever
received had no surviving citation, and the code said so instead of storing it as fact — which is
the entire point of enforcing grounding in code rather than asking the model nicely.

## What P3 built

| Area | Artefact | The decision that matters |
|---|---|---|
| Schemas | `llm/schemas.py` | `extra="forbid"` on every gate output; `Quote` refuses non-http URLs; a fenced ```json block is accepted, anything else is a violation with its location |
| Grounding | `enforce_grounding` | a quote survives only if its URL is one the pipeline collected; a stripped verdict is **marked** `ungrounded`, never deleted — what cannot stand is presenting it as cited fact |
| Cache | `llm/cache.py` | 30-day TTL keyed by `sha256(gate \| model \| normalized input)`; the model is in the key or the failover chain would mix providers; expiry checked on read *and* sweepable; the cache doubles as the token log |
| Gateway | `llm/gateway.py` | chain order from §6.3, failover on error, one schema retry per entry, bounded transient retries, caps that degrade with a reason and never retry blindly, cache-before-provider, injected transport |
| Transports | `llm/providers.py` | four real providers; a **missing key is an error, not a skip** (that is how the unkeyed Groq entry exercises failover); every request passes the egress allowlist |
| Judge | `llm/gates.py` | batches candidates (default 10/call), evidence assembled in one query, verdicts applied to `candidates.status`, judgements persisted, unknown phrases ignored, a degraded gate changes **nothing** |
| Storage | migration 0002 + `judgements` | append-only table (deviation D12) with the citations, the enrich list, the model, the cache key and the token counts |
| Replay | `llm/replay.py` + `scripts/judge_replay.py` | the whole gate over a recorded answer, offline, with a `--fresh` cache bypass so the accounting is real |
| Viewer | `viewer/` | a **judge column**, a **Gates** section (verdicts, keep/drop, no-citation count, quotes stripped, token log per gate) and a per-item **Gate advice** panel with the cited quotes, the reason and the enrichment request |

## Bugs this phase found

1. **Grounding was silently bypassed for batches.** `enforce_grounding` looked for a `.quotes`
   attribute, which a `JudgeBatch` does not have — so the rule did nothing on the exact path the
   Judge uses, and every invented citation in a nightly batch would have been stored as fact.
2. **The raw lake insert was not idempotent.** Two payloads with the same content hash inside one
   run raised a `UniqueViolation` and took the source down. Now `ON CONFLICT DO NOTHING`.
3. **"Newest hash" is not dedup.** With several payloads per run, comparing against the most recent
   row masks the others, so the next run re-parsed everything (the gate's L0 probe caught a second
   run parsing 12 payloads it should have skipped). Dedup is now a set lookup over recent hashes.
4. **`--json` printed two concatenated documents** when a command ran two phases — no consumer can
   parse that, and the gate's own probe tripped over it. One command, one document, phases nested.
5. **A replay that hit the cache proved nothing about tokens** (0+0 in the accounting columns).
   Hence `--fresh`: a replay must exercise the whole path.
6. **The replay answered every batch with one recording**, because it matched the phrase against
   the whole queue instead of the batch's prompt — it looked like a model inventing candidates.

**Six bugs, five of them "a check that measured nothing".** That is the pattern of this phase: the
gateway logic was right early, and what kept being wrong was the *evidence* that it worked.
