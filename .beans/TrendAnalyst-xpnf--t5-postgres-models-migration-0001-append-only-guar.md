## Summary of Changes

The full schema of spec §7, with history and side effects made physically un-rewritable.

- **11 tables** (store/models.py, typed SQLAlchemy 2 Mapped[]): sources, runs,
  run_source_log, raw_items, signals, candidates, scores, briefs, quota_ledger,
  llm_cache, eval_cases — with a fixed constraint-naming convention so Alembic names stay
  reviewable, timestamptz everywhere, and CHECK constraints that mirror the registry
  (Tier A never in L0, budget > 0, rps > 0, revenue P10<=P50<=P90, ordered score band).
- **migrations/0001_initial** — autogenerated, then extended by hand with the three
  things autogeneration cannot express: the guarded pgvector extension, the append-only
  triggers, and the quota_spend_daily view. Fully reversible (downgrade base works);
  the extension is deliberately NOT dropped on downgrade.
- **Append-only history (spec §5.3/§5.4)** — triggers on scores, briefs and quota_ledger
  reject UPDATE and DELETE outright, so a bug in application code can only append a
  correction, never rewrite history. Proven by tests that attempt both.
- **Compare-and-swap (spec §5.4)** — UNIQUE (run_id, source_id, operation) on
  quota_ledger makes a resumed run physically unable to double-spend; UNIQUE
  (run_id, candidate_id) on briefs makes a double-emit impossible; UNIQUE
  (source_id, content_hash) on raw_items is the dedup key of spec §5.2.
- **store/db.py** — engine from layered settings (pool_pre_ping, connect_timeout,
  statement_timeout), session_scope (commit/rollback), and check_database() which reports
  down-as-a-status rather than raising, because health must be able to print 'down, with a
  reason' (spec §9).
- **Isolated test database** — tests run against trend_analyst_test, created by the
  provisioning script, so a test may migrate up and down freely; each test runs inside a
  transaction that is always rolled back.

### The bug this task found (worth remembering)
Every DB connection from Windows took **130 seconds** and looked like a hang: on Windows
 resolves to IPv6  first, and WSL's port relay black-holes , so the
client waits out the TCP timeout before falling back to IPv4. Measured: 130.09 s via
, 0.06 s via . Fixed by generating the DSN with 127.0.0.1 (README
D8), and by giving migrations connect_timeout + lock_timeout so a schema change fails fast
instead of hanging. The migration round trip now takes 2.8 s.
